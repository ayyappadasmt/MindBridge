## Infrastructure Audit Summary

### Issues Found & Fixed

| File | Issue | Fix Applied |
|------|-------|-------------|
| `bigquery_service.py` | Hardcoded `serviceAccountKey.json`; undefined `TABLE_REF` variable | ADC credentials; `settings.bigquery_table_ref` property |
| `firestore_service.py` | Hardcoded file path, fails in Cloud Run | ADC + Secret Manager JSON fallback |
| `main.py` | Wildcard CORS `allow_origins=["*"]` | Restricted to `ALLOWED_ORIGINS` env var |
| `main.py` | No authentication middleware | Firebase ID token middleware added |
| `vertex_ai_config.py` | Hardcoded `project="mindbridge-dev-member2"` | Reads from `PROJECT_ID` env var |
| `config.py` | No validation on `PROJECT_ID` | Pydantic validator raises on empty/default |
| `Dockerfile` | Single-stage, runs as root | Multi-stage build, non-root `appuser` |
| All services | Secrets shipped in image or env | Secret Manager + ADC |

## Step-by-Step Deployment

### Prerequisites

```bash
# Install tools
brew install google-cloud-sdk  # or apt-get
gcloud auth login
gcloud auth application-default login

export PROJECT_ID=your-gcp-project-id
export REGION=us-central1
gcloud config set project $PROJECT_ID
```

### Step 1 — IAM Setup (run once)

```bash
bash infra/iam/setup_iam.sh
```

Creates two service accounts:
- `mindbridge-backend` — used by Cloud Run (Vertex AI, BigQuery, Firestore, Secret Manager)
- `mindbridge-cicd` — used by Cloud Build (Artifact Registry push, Cloud Run deploy)

No `Owner` or `Editor` roles are granted anywhere.

### Step 2 — BigQuery

```bash
bash infra/bigquery/setup_bigquery.sh
```

Creates `mindbridge_insights.distress_events` table partitioned by day. Schema stores **no PII** — only `event_id`, `timestamp`, `region_id`, `stress_category`, `distress_level`, `platform`.

### Step 3 — Secret Manager

```bash
export FIREBASE_KEY_FILE=./serviceAccountKey.json
bash infra/setup_secrets.sh
```

Stores Firebase service account JSON in Secret Manager as `firebase-service-account`. Cloud Run mounts this as the env var `FIREBASE_SERVICE_ACCOUNT_JSON`.

**The key file never enters the Docker image.**

### Step 4 — Firebase Configuration

```bash
bash infra/firebase/setup_firebase.sh
```

Then in Firebase Console:
1. Enable **Google Sign-In** and **Anonymous Sign-In**
2. Copy the web SDK config for Member 3's frontend
3. Deploy Firestore security rules (file generated by the script)

### Step 5 — First Deployment (manual)

```bash
bash infra/deploy.sh
```

This:
1. Creates the Artifact Registry Docker repo
2. Builds the multi-stage Docker image (amd64)
3. Pushes to Artifact Registry
4. Deploys to Cloud Run with all env vars and secrets

### Step 6 — API Gateway

After Step 5, get the Cloud Run URL:
```bash
gcloud run services describe mindbridge-backend \
  --region=$REGION --format="value(status.url)"
```

Edit `infra/apigateway/openapi.yaml` — replace `REPLACE_HASH` and `REPLACE_PROJECT_ID` with actual values. Then:

```bash
gcloud api-gateway apis create mindbridge-api --project=$PROJECT_ID

gcloud api-gateway api-configs create mindbridge-config-v1 \
  --api=mindbridge-api \
  --openapi-spec=infra/apigateway/openapi.yaml \
  --project=$PROJECT_ID \
  --backend-auth-service-account=mindbridge-backend@$PROJECT_ID.iam.gserviceaccount.com

gcloud api-gateway gateways create mindbridge-gateway \
  --api=mindbridge-api \
  --api-config=mindbridge-config-v1 \
  --location=$REGION \
  --project=$PROJECT_ID
```

### Step 7 — CI/CD (GitHub → Cloud Build)

```bash
# Connect your GitHub repo in Cloud Build console:
# https://console.cloud.google.com/cloud-build/triggers

# Or via CLI:
gcloud builds triggers create github \
  --repo-name=mindbridge \
  --repo-owner=YOUR_GITHUB_ORG \
  --branch-pattern="^main$" \
  --build-config=cloudbuild.yaml \
  --service-account=projects/$PROJECT_ID/serviceAccounts/mindbridge-cicd@$PROJECT_ID.iam.gserviceaccount.com \
  --project=$PROJECT_ID
```

After this, every push to `main` → tests → Docker build → Artifact Registry → Cloud Run deploy.

## Production Deployment Checklist

### Security
- [ ] No secrets in Docker image or git
- [ ] Firebase service account stored in Secret Manager
- [ ] CORS restricted to actual frontend domain in `ALLOWED_ORIGINS`
- [ ] Firebase auth middleware active on all routes except `/health`
- [ ] Firestore security rules deployed (users only access own data)
- [ ] Cloud Run service account has no `Owner`/`Editor` roles
- [ ] `.env` file in `.gitignore` and `.dockerignore`

### Infrastructure
- [ ] All GCP APIs enabled
- [ ] Artifact Registry repository created
- [ ] BigQuery dataset + table created
- [ ] Cloud Run deployed with correct SA
- [ ] API Gateway deployed and URL given to Member 3

### CI/CD
- [ ] Cloud Build trigger connected to GitHub main branch
- [ ] `cloudbuild.yaml` committed to repo root
- [ ] Test push confirms auto-deploy works

### Functionality
- [ ] `GET /health` returns 200
- [ ] `POST /pathway/analyze` with valid Firebase token returns pathway
- [ ] BigQuery logs appear after pathway call
- [ ] FCM notification sends successfully

## Local Development

```bash
# 1. Copy env template
cp .env.example .env
# Fill in PROJECT_ID, FIREBASE_SERVICE_ACCOUNT_KEY, etc.

# 2. Install deps
pip install -r requirements.txt

# 3. Run
uvicorn app.main:app --reload --port 8080
```

For local dev, set `ENVIRONMENT=development` — this enables `/docs` (Swagger UI) and uses the file-based Firebase key.

## IAM Role Summary

| Service Account | Resource | Role | Why |
|---|---|---|---|
| `mindbridge-backend` | Project | `roles/aiplatform.user` | Call Gemini models |
| `mindbridge-backend` | Project | `roles/bigquery.dataEditor` | Insert anonymized events |
| `mindbridge-backend` | Project | `roles/bigquery.jobUser` | Run queries |
| `mindbridge-backend` | Project | `roles/datastore.user` | Firestore read/write |
| `mindbridge-backend` | Secret | `roles/secretmanager.secretAccessor` | Read Firebase key |
| `mindbridge-backend` | Project | `roles/firebase.sdkAdminServiceAgent` | Verify auth tokens |
| `mindbridge-cicd` | Project | `roles/run.developer` | Deploy new revisions |
| `mindbridge-cicd` | Project | `roles/artifactregistry.writer` | Push images |

**Roles NOT granted:** `roles/owner`, `roles/editor`, `roles/iam.admin`
